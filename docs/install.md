# 安装与维护

## 系统要求

- Windows x64，《Turing Complete》2.1.334 指定构建（哈希见下文）。
- 游戏目录必须可写。玩家侧不需要 Python、Node.js、MinGW 或额外启动器。

## 安装 / 升级

1. 关闭要安装的那份游戏。
2. 双击 `TCModLoader-Setup.exe`。
3. 窗口左栏列出自动找到的安装位置（Steam 各库 ＋ 本次手动添加）；没有找到时点
   `＋ 添加其他位置` 选 `Turing Complete.exe`，**选完回到主窗口**，不会立刻写文件。
4. 选中一个位置，右栏先给出结论：游戏版本、兼容性、Mod Loader 状态、两三条安全检查。
   主按钮只有一个——`安装到此位置`／`修复安装`／`升级到 0.8.5`。
5. 点主按钮。窗口不会关闭，右侧原地显示阶段（正在再次检查游戏／正在备份原始引擎／正在安装
   Mod Loader／正在验证安装结果），完成后变成结果横幅，可直接 `打开 Mods 文件夹`。
6. 把 `.mod` 文件直接放入游戏根目录的 `mods/` 文件夹，不要解压。
7. 正常启动游戏，点击主菜单右上角 **Mods**，勾选并“应用更改”。
8. 关闭并重新启动游戏。管理页会区分“下次启动启用”与“本次运行中”。

可从已验证的 0.1.0／0.2.0／0.3.0 安装直接升级。

安装前请先看清右栏的结论，安装器不会"强行"安装：

| 右栏显示 | 说明 |
|---|---|
| `无法安装到此位置` | `Turing Complete.exe` 或 `game_engine.dll` 不是受支持的构建，安装器**只读** |
| `已禁用安装` | 当前引擎不认识，或者原始引擎备份缺失、损坏；覆盖它会让玩家无法回到原版 |
| `关闭游戏后重试` | 这份游戏正在运行（只认选中的那一份，不影响你别的副本） |
| `使用管理员权限安装` | 游戏目录不可写；点它只会在需要时弹出 UAC，取消即"未进行任何更改" |

其余情况：目录不可写、游戏正在运行、备份异常都会在**安全检查**里逐条写明原因；
`更多操作 → 查看技术信息`展开路径、实际/期望的 SHA-256、兼容配置与进程状态，并可以一键复制。

## 卸载

关闭该份游戏，再运行同版本安装器，选中同一个位置，点 `更多操作 → 卸载并恢复原始引擎…`，
在右栏出现的确认区里点 `确认卸载并恢复`：`game_engine.dll` 回到原版，Mod 包、配置、
`tc-modloader-data/` 和独立存档都留在原处。游戏 EXE 本身从不被修改。

卸载与安装不等重——它不在主按钮上，必须先展开 `更多操作`，避免误触。

资源文件若被外部工具或游戏更新改动，加载器会拒绝强行覆盖。不要在资源 Mod 启用期间
删除备份目录。

## 独立存档与原版导入

从 0.3.0 起，装有加载器的游戏始终使用独立存档，即使全部 Mod 停用或按住 Shift 跳过
原生插件也一样；首次启动默认是一份新存档。

| 用途 | 位置 |
|---|---|
| 原版存档 | `%USERPROFILE%\AppData\Roaming\Turing Complete` |
| Mod 默认存档 | `%USERPROFILE%\AppData\Roaming\Turing Complete Mods\profiles\default` |
| 导入副本 | 上述 profiles 目录中的 `import-<随机编号>` |

主菜单右上角 **Mods 下面的「存档」** 是加载器自己的存档管理页（和 Mod 列表分开，互不干扰）：

| 操作 | 说明 |
|---|---|
| 新建存档 | 开一份空副本（`local-<随机>`）并设为下次启动使用 |
| 导入原版存档 | 把原版存档整份复制成 `import-<随机>` 副本，逐文件校验 |
| 切换到这一份 | 写 `saves.ini`，**重启游戏后生效** |
| 复制副本 | 把选中的副本整份复制成 `copy-<随机>`（也做逐文件校验） |
| 重命名 | 只能用 `a-z 0-9 -`，最长 64 字符；不合并其它副本 |
| 删除到回收站 | 移成 `trash-<原名>-<时间戳>`，**不直接删除**，改回名字即可恢复；当前使用的副本不能删 |
| 打开文件夹 | 在资源管理器里打开该副本目录 |

页面上每行显示副本名、占用大小、文件数、最后修改时间，以及「本次运行 / 下次启动 / 导入副本」
标记；详情里第一行就是这份存档的 **Mod 依赖**结论（缺失几项 / 已装未启用 / 版本不同，或"都用到了
的 Mod 都装好并启用了"），下面是逐条明细：每个用到的自定义元件属于哪个 Mod、什么版本，缺失的用红色
标出，加载器没见过的类型显示作者写的 8 字节标记。点「重新扫描」可以重算。

这份清单是本地推算出来的：游戏的电路文件里只有每个自定义元件的 64 位 `custom_id`，加载器在元件
注册时把「id → Mod / 类型 / schema / 版本」记在 `tc-modloader-data/registry.json`，因此**本机
曾经装过并加载过的 Mod 都能点名**；从未见过的类型只能给标记，不会猜 Mod 名字。

- 导入包含本机关卡进度、设置与电路文件，每次新建副本、逐文件校验；不改原版、
  不合并或覆盖已有 Mod 存档；导入失败不切换存档。
- 运行中的游戏继续使用原副本，重启后才切换。
- Steam 云元数据 `steam_autocloud.vdf` 不复制；这不是云存档下载功能。
- 存档路径在游戏初始化前重定向，只改进程内专用路径常量，磁盘 EXE 不变。此构建实际按
  `USERPROFILE` 拼接路径，所以仅设置 `APPDATA` 不能隔离。
- 当前副本选择保存在 `<游戏目录>/tc-modloader-data/saves.ini`；同 Windows 用户下不同
  游戏安装共享 profiles 目录，但各自的选择独立。管理页做的切换/新建/导入都只改这个文件，
  运行中的游戏继续用启动时选定的那份。

卸载加载器后游戏恢复原版路径，Mod 存档仍保留，绝不自动写回原版；建议同时备份原版与
Mod 存档。原生插件若自行硬编码其他路径，加载器无法阻止它绕开游戏存档接口。

## 启停、更新与恢复

- 原生插件启停与更新需要重启游戏，不支持热卸载。重新打开 Mods 页面会扫描新包，也可
  点击“刷新列表”。
- 原生包应用时记录 SHA-256；包被替换后不会按旧启用状态自动执行新代码，需重新应用并
  重启。
- 依赖先加载；循环依赖被拒绝，依赖失败会阻止依赖它的插件启动。
- 两个 Mod Hook 同一函数时，后加载者失败并在管理页显示状态，不做隐式 Hook 串联。
- 插件初始化失败会撤销它已注册的 Hook，并在日志中说明原因。
- 原生 DLL 与游戏同权限，不在沙箱中；加载器不能可靠隔离原生代码的访问违规或崩溃。
- 启动时按住 Shift 并保持到主菜单出现，可跳过本次所有原生插件，再进入管理页停用问题包。
- 无法进入游戏时，关闭该份游戏后用 `tools/tcmod-cli.exe <游戏目录> disable-all` 保存
  全部停用状态。

日志位于 `<游戏目录>/tc-modloader-data/loader.log`；日志格式与排查方法见
[reference/diagnostics.md](reference/diagnostics.md)。

## 文件位置

| 路径 | 内容 |
|---|---|
| `game_engine.dll` | 加载器代理（原引擎被改名为 `tc_game_engine.dll`） |
| `mods/*.mod` | 玩家分发的包 |
| `tc-modloader-data/state.json` | 部署状态与原生包指纹 |
| `tc-modloader-data/blobs/` | 资源原文件备份 |
| `tc-modloader-data/plugins/<id>/<包指纹>/` | 原生 DLL 缓存 |
| `tc-modloader-data/plugin-data/<id>/` | 插件的持久数据目录；`storage/` 是宿主管理的 GLOBAL 配置 |
| 当前 profile 下的 `tc-mod-data/<id>/` | `tc.mod.storage` 的 PROFILE 数据；复制/重命名/删除 profile 时一起处理 |
| `tc-modloader-data/loader.log` | 运行日志 |

安装包不包含原游戏 EXE 或引擎。原生 DLL 从缓存载入游戏进程，不覆盖游戏自身 DLL。

## 兼容构建

界面版本号 2.1.334，并严格校验以下 SHA-256：

```text
Turing Complete.exe
8875da0e88cc878cb0fce30cfb63d20c5500cae341608af4d786649b88c8eb21

原版 game_engine.dll
0a4030b5f5538cc3682610ac3e7b39e8e31ec34f9aeafe7a1d036bfa33819166
```

游戏更新后需重新适配，不能简单关闭哈希检查。旧 Godot PCK、BepInEx 或 Lua Mod 不能直接
用于本 SDK。可在安装前运行 `tools/compat.ps1 -GameDirectory <游戏目录>` 查看具体画像和文件
证据；画像维护流程见 [compatibility.md](compatibility.md)。

**游戏更新之后会发生什么（0.8.0 起）**：加载器**不会**再阻止游戏启动。它会照常让游戏跑起来，
但这次运行：

1. 不重定向存档——游戏用它自己的存档目录，玩家原本的进度不受影响；
2. 不加载任何原生插件（资源 Mod 仍然生效），避免 Mod 写进玩家的真实存档；
3. 弹一次提示框说明"加载器与这份游戏不匹配"，并在
   `<游戏目录>/tc-modloader-data/unsupported-build.txt` 记下这次不匹配的加载器版本与游戏哈希
   （同一组合只提示一次，不会每次启动都弹）；
4. 把原因写进 `loader.log`。

处理方式：安装与新游戏版本匹配的加载器，或者运行安装器卸载加载器（卸载会恢复原引擎文件）。
这也是为什么主菜单在这种状态下**看不到 Mods 按钮**——加载器知道的对齐点已经不可信，绘制自己的
界面本身就不安全。

## 排错

| 现象 | 处理 |
|---|---|
| 主菜单没有 Mods 按钮 | 确认加载器已安装到该份游戏，且未同时运行原版启动器 |
| 管理页显示包存在但状态异常 | 查看 `loader.log` 中该包 id 的日志行，按 [diagnostics.md](reference/diagnostics.md) 定位 |
| 装了新包但行为没变 | 需要在管理页重新“应用更改”并重启；包被替换后指纹不匹配会被拒绝 |
| 游戏崩溃或卡在启动 | 关闭游戏，按住 Shift 启动跳到主菜单，进入 Mods 停用问题包后重启 |
| 游戏更新后 Mods 不见了、还弹了一次提示 | 正常降级：本次运行没有加载原生插件、也没有重定向存档。装匹配新版本的加载器即可；详情见 `tc-modloader-data/unsupported-build.txt` 与 `loader.log` |
