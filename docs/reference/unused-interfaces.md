# 未使用接口登记

这里登记**已经交付、契约已冻结、但当前没有任何 Mod／示例在棋盘上真的用**的能力与开关。
写在这里不等于废弃：目的是两件事——不要重复发明；要用时知道怎么接回来（参数、证据、动哪个文件）。

规矩：每条写清"能做什么 / 谁在测它 / 为什么不投入使用 / 接回来要改什么"。启用或删除一条时，
这里和 `changelog.md` 各记一笔。

## 1. 模仿原版那圈选中提示（断环）

**能做什么**：用 `tc.component.render` V1 的折线图元，照游戏原版那圈白色断环画选中提示；游戏自己那圈
已经能按类型关掉（V3 `set_selection_hint(id,false)`），所以不会重影。尺寸与圆心是 Mod 自己的参数，
这正是原版做不到的事（见 [verification.md](../verification.md)「模仿原版那圈提示」）。

**原版几何（2026-09-23 实测，两个相机缩放）**：

| 属性 | 值 |
|---|---|
| 环心 | 元件原点 **+1.00 板面格**（局部 x；实测 0.99/0.97 格） |
| 半径 | 内缘 **0.80 格**，线宽 **0.21 格** → 中心线半径 0.91 格 |
| 弧段 | **44°–137°** 与 **223°–315°**（+x 为 0°、+y 向下），左右各留约 86° 缺口 |
| 颜色 | 253,253,253（近纯白） |
| 缩放 | 随板面缩放（unit 28.16 时 540 px、21.157 时 304 px，面积 ∝ 缩放比²），不是固定像素 |

**谁在测它**：只有一次性原型与诊断。原型做过同帧对拍（游戏白环 + 橙色模仿环）：模仿环 443 px、
原版未被盖住的只剩 84 px，外接框差 1–2 px（抗锯齿边）；形状断言"环上 10 条射线命中、缺口 6 条落空"
实测 10/10 与 0/6。证据图 `build/text-box-out/hint-imitation-overlay.png`、`hint-imitation.png`、
`hint-imitation-both.png`、`hint-imitation-custom.png`（最后一张是半径 2.4 格、圆心居中的自由参数演示）。
重新量原版几何用 `TC_TEXTBOX_ARC_ZOOM_OUT=<n>` 把便签选中后再缩小 n 档。

**为什么不投入使用**：2026-09-23 用户决定——便签的选中提示继续用"跟着声明的 footprint 的矩形"，因为
它同时就是可拖区，信息量比一个装饰环大；模仿环从示例里撤出，原型参数与证据留档于此。

**接回来要改什么**：在 `examples/text-box/plugin.cpp` 的 `renderNoteOutline()` 选中分支里加一段折线绘制
（两个弧段各采样约 20 个点，线宽 = `0.21 * unit`，`unit` 取自 `renderFrame->axis_x_*`），把上表三个
数字做成开关；门禁在 `tests/text-box-playtest.ps1` 里加"环上射线命中 / 缺口射线落空"的断言。

## 2. `tc.component.render` V1 的四个图元

**能做什么**：`rect`（描边矩形）、`circle`（描边圆）、`circle_filled`（填充圆）、`text`（宿主默认字体
文本）。宿主侧实现、参数校验与每实例每帧 4096 条配额都已就绪。

**谁在测它**：只有 `tests/component-render.cpp` 校验 API 表布局与错误码，没有棋盘上的使用者：
`examples/text-box` 只用 `line` 与 `rect_filled`（正文是插件自己用 ImGui 画的）。

**为什么没投入使用**：文本框当前用不到描边矩形、圆与宿主文本；`text` 的中文/字号能力要等资源切片
（M5 剩余项里的"字体资源生命周期"）。

**接回来要改什么**：直接调用即可，无需改宿主；用 `text` 前先确认默认字体的字形覆盖。

## 3. `set_selection_hint(id, 1)`（把游戏那圈还回去）

**能做什么**：撤销 V3 的关闭动作，让该类型重新使用游戏自己的选中提示。默认就是开的，只有已经关过的
类型需要调用。

**谁在测它**：`tests/component-render.cpp` 的表布局；文本示例的对照组走的是"不调用关闭"而不是"调用
恢复"（`TC_TEXTBOX_KEEP_ARCS=1`）。

**为什么没投入使用**：目前没有"按设置动态切换提示样式"的需求。

**接回来要改什么**：语义与 V2 的 `set_default_drawing(…,1)` 一致，直接调用；在真机门禁里补一条
"调用后白弧重新出现"的断言（现成做法：`TC_TEXTBOX_KEEP_ARCS=1` 那套像素量法）。

## 4. `set_foundry_button(id, 1)`（把"在元件工坊编辑"按钮还回去）

**能做什么**：撤销 V4 的隐藏动作，让该类型重新显示游戏自己的工坊按钮。默认就是显示的，只有已经关过的
类型需要调用。

**谁在测它**：`tests/component-render.cpp` 校验表布局与两个方向的包装函数；示例 Mod 的对照组走的是
"不调用关闭"（`TC_TEXTBOX_FOUNDRY_BUTTON=1`），而不是"调用恢复"。

**为什么没投入使用**：目前没有"按设置动态切换这个按钮"的需求。

**接回来要改什么**：语义与 V2/V3 的 `…(…,1)` 一致，直接调用；真机门禁补一条"调用后按钮像素回来"的
断言（现成量法：`TC_FOUNDRY_TRACE=1` 报出的矩形 + 数亮像素，默认关掉是 0、保留是 654）。

## 附：当前没有任何脚本使用、只在人工诊断时开的开关

以下都是示例 Mod（`examples/text-box`）的开关，**没有进任何门禁脚本**，只服务于人工研究：

| 开关 | 用途 |
|---|---|
| `TC_TEXTBOX_OUTPUT_PIN=1` | 把便签切回"1 根悬空输出脚"的旧形状（真 0 脚之前的对照） |
| `TC_TEXTBOX_FOREGROUND_TEST=1` | 在前景绘制列表上盖一块不透明补丁，用来判断哪一层压在游戏的选中弧之上 |
| `TC_TEXTBOX_ARC_ZOOM_OUT=<n>` | 弧线场景选中后缩小 n 档，用来量游戏那圈是否随板面缩放 |
| `TC_TEXTBOX_HINT_ORANGE=1` | 自绘提示改成橙色（诊断色，便于与游戏的白色弧区分） |
| `TC_TEXTBOX_DRAG_PROBE=0` | 跳过拖动阶段（分离"拖动残留"与"关掉绘制"） |
| `TC_TEXTBOX_FOUNDRY_BUTTON=1` | 保留游戏自己的"在元件工坊编辑"按钮（V4 的对照运行） |
| `TC_FOUNDRY_TRACE=1` | 宿主把那个按钮的矩形与"是否被隐藏"每秒写进日志（门禁在弧线场景自动打开） |
