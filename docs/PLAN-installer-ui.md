# TC Mod Loader 安装器界面实现方案

日期：2026-09-27。状态：**第一刀到第三刀已完成**（`docs/verification.md` 的"安装器窗口"一节有
逐条证据）；第四刀里图标、版本资源、DPI manifest、键盘操作、高对比度适配已完成，**还差发布截图**
（截图需要随发行版一起挑，仓库目前不放图片）。

落地形状与本文的差别只有两处，都是执行时判断的：

1. 拆分粒度按 §6 执行，但"安全检查"的两三条文案与色调也放进 `setup_state`（纯函数），因为计划 §10
   要求状态到主动作的映射可逐项测试，文案同属该规则；
2. 结果横幅与确认区**替换**右栏的"安全检查"块（同一位置、同一个固定层级），这就是 §7 说的
   "右侧详情原地变成成功状态"；空档位置不放占位内容。

## 1. 目标

把当前“选择 `Turing Complete.exe` → MessageBox 选择安装或卸载”的流程，改成一个单窗口的
Windows 桌面安装中心。界面采用已选定的第三套方向：左侧列出检测到的游戏安装位置，右侧显示所选
位置的兼容性、Mod Loader 状态、安全检查和当前可执行操作。

首发版本只解决加载器自身的安装与维护，不在安装器里管理单个 `.mod` 包。游戏内的 Mods 页面仍是
唯一的 Mod 启停入口。

### 玩家需要得到的答案

打开安装器后，玩家不需要理解 DLL 或文件哈希，也能立即知道：

1. 找到了哪一份游戏；
2. 这份游戏是否兼容；
3. Mod Loader 当前是未安装、可升级、已安装还是需要修复；
4. 点击主按钮会发生什么；
5. 安装失败后是否改动了游戏，以及下一步应该怎么做。

## 2. 首发范围

### 包含

- 自动发现 Steam 中常见的 Turing Complete 安装位置；
- 手动添加包含 `Turing Complete.exe` 的目录；
- 同时展示多个安装位置，但一次只操作一个；
- 严格执行现有 EXE、原版引擎和已知旧加载器哈希检查；
- 安装、升级、修复、卸载并恢复原文件；
- 显示游戏正在运行、目录不可写、备份损坏、版本不兼容等状态；
- 打开游戏目录、Mods 文件夹和安装日志；
- 操作完成后留在当前窗口并重新检查状态；
- 保留 `--install <目录>` 和 `--uninstall <目录>` 无界面模式，供测试和脚本使用。

### 不包含

- Mod 商店、下载器或在线更新器；
- 单个 Mod 的安装、启停、排序和依赖处理；
- 游戏启动器；
- 自动删除 Mod、配置、日志或独立存档；
- 绕过未知游戏版本或未知 `game_engine.dll` 的“强制安装”；
- 原生 DLL 热更新。

## 3. 界面结构

建议初始客户区约为 `960 × 640 DIP`，允许放大，最小尺寸约为 `820 × 560 DIP`。布局分为顶部标题、
左侧安装位置列表和右侧详情区。

### 顶部

- 标题：`选择要管理的游戏`
- 副标题：`检测到 N 个 Turing Complete 安装位置`
- 右上角显示安装器版本，例如 `安装器 0.8.0`

### 左侧：安装位置

每项只显示三类信息：来源、路径、兼容状态。

```text
Steam
D:\SteamLibrary\steamapps\common\Turing Complete
● 兼容
```

状态使用图标、文字和颜色共同表达，不能只靠颜色。列表末尾固定提供 `添加其他位置`。手动添加时仍可
使用系统文件选择器，但选择完成后返回主窗口，不再立刻安装。

若没有自动发现任何位置，左侧显示空状态：

```text
没有自动找到游戏
选择 Turing Complete.exe 所在位置
[选择游戏位置]
```

### 右侧：所选位置详情

详情区从上到下保持固定层级：

1. 游戏名称、来源和完整路径；
2. 游戏版本、兼容性、Mod Loader 状态；
3. 两到三条与本次操作有关的安全检查；
4. 一个主操作按钮；
5. `更多操作` 菜单；
6. 一行不会删除哪些数据的说明。

主按钮随状态变化：

| 状态 | 主按钮 | 次要操作 |
|---|---|---|
| 兼容、未安装 | 安装到此位置 | 打开游戏目录 |
| 已安装当前版本 | 修复安装 | 卸载并恢复、打开 Mods 文件夹、查看日志 |
| 已安装已知旧版本 | 升级到 0.8.0 | 卸载并恢复、查看日志 |
| 游戏正在运行 | 关闭游戏后重试 | 打开游戏目录 |
| 游戏版本不兼容 | 不提供安装按钮 | 查看技术信息、选择其他位置 |
| 备份缺失或损坏 | 不提供破坏性按钮 | 查看技术信息、打开游戏目录 |
| 目录不可写 | 使用管理员权限安装 | 打开游戏目录 |

卸载不与安装并列成同等醒目的第二个大按钮，避免新用户误触。它放在 `更多操作` 中，点击后使用内联
确认区说明“恢复原始引擎，但保留 Mod、配置和存档”，不使用含义模糊的“是/否”对话框。

## 4. 状态模型

界面不直接根据某一个文件是否存在来猜按钮。每个位置先生成完整只读快照，再由纯状态规则决定文案和
动作。

建议的数据结构：

```cpp
enum class Compatibility {
    checking,
    compatible,
    unsupported_exe,
    unsupported_engine,
    unreadable
};

enum class LoaderState {
    not_installed,
    installed_current,
    installed_previous,
    installed_unknown,
    backup_missing,
    backup_invalid
};

struct InstallationSnapshot {
    std::filesystem::path root;
    std::wstring source_label;
    Compatibility compatibility;
    LoaderState loader_state;
    bool game_running;
    bool directory_writable;
    std::string exe_sha256;
    std::string engine_sha256;
    std::string backup_sha256;
    std::wstring summary;
    std::wstring technical_detail;
};
```

所有检查必须是只读的。只有玩家点击明确操作后才进入写入路径。

窗口自身再维护一个简单状态机：

```text
scanning → ready → confirming → working → success
                              └──────────→ failure
```

`working` 期间禁用位置切换和关闭窗口，并显示当前阶段，不显示无法保证准确的百分比：

- 正在再次检查游戏；
- 正在备份原始引擎；
- 正在安装 Mod Loader；
- 正在验证安装结果。

## 5. 游戏位置发现

按以下顺序合并并去重候选目录：

1. 命令行显式传入的目录；
2. Steam 当前库和额外库中对应的游戏目录；
3. 本次运行中玩家手动添加的位置。

Steam 检测失败不应成为安装器错误，只退化到手动选择。候选目录必须最终包含
`Turing Complete.exe` 和 `game_engine.dll`，规范化为绝对路径后按大小写不敏感方式去重。

首发版不必持久化“最近使用位置”。如果后续确有非 Steam 用户反复维护多个副本的需求，再把用户确认
过的位置记录到 `%LOCALAPPDATA%\TCModLoader\installer.json`；不要在第一版引入迁移和清理负担。

## 6. 技术方案

### UI 技术

继续使用原生 Win32，保持单 EXE、无需 WebView2、.NET 或额外运行库。界面采用混合实现：

- Direct2D / DirectWrite 绘制背景、排版、状态图标和分隔线；
- 交互元素使用真实 Win32 子控件并做 owner-draw，保留键盘焦点、Tab 顺序和基础辅助功能；
- 启用 Per-Monitor V2 DPI 感知；
- 默认跟随系统深浅色；高对比度模式下退回系统颜色；
- 字体优先使用 Segoe UI Variable / Segoe UI，让 DirectWrite 自动完成中文字体回退。

不建议为了这一页引入 WinUI 3、Qt 或 Web 技术。它们会显著增大发行体积和部署变量，而当前界面只有
一个窗口和少量状态。

### 代码拆分

当前 `src/setup.cpp` 同时包含参数解析、进程检查、兼容判断、文件写入和 MessageBox UI。先拆出已有逻辑，
在行为不变的前提下形成以下边界：

```text
src/setup.cpp             程序入口、命令行模式选择
src/setup_core.hpp/.cpp   inspect/install/repair/uninstall；不包含 UI
src/setup_discovery.*     Steam 与手动位置发现、规范化、去重
src/setup_window.*        Win32 窗口、布局、绘制、输入和状态映射
src/setup_resources.rc    内嵌 loader、图标、版本与 DPI manifest
```

核心层不直接弹框，返回结构化结果：

```cpp
enum class SetupError {
    none,
    game_running,
    unsupported_exe,
    unsupported_engine,
    backup_missing,
    backup_invalid,
    permission_denied,
    io_error,
    verification_failed
};

struct SetupResult {
    SetupError error;
    std::wstring user_message;
    std::wstring technical_detail;
};
```

原有哈希白名单、`no_links`、原子替换、备份校验和拒绝覆盖规则原样保留。UI 只能选择允许的动作，不能
弱化核心层的二次检查。

### 后台工作

目录扫描、文件哈希和安装操作在工作线程执行，通过窗口消息把不可变结果发回 UI，避免大文件校验时窗口
假死。写入开始后不提供“取消”按钮；这些操作很短，并且中途取消会让恢复语义更难说明。窗口关闭请求在
提交阶段应被阻止，并显示“正在完成安全写入”。

### 权限提升

先检查目标目录能否安全写入，不在启动时无条件请求管理员权限。只有确实需要时，主按钮改为
`使用管理员权限安装`，用 `runas` 重新启动同一个 EXE 的现有无界面命令：

```text
TCModLoader-Setup.exe --install "<游戏目录>"
```

父窗口等待提升进程退出，然后重新扫描并展示实际结果。取消 UAC 不算安装失败，文案应为“未进行任何
更改”。

## 7. 反馈与错误文案

成功后不弹额外 MessageBox，右侧详情原地变成成功状态：

```text
Mod Loader 0.8.0 已安装
原始引擎已安全备份

[打开 Mods 文件夹]  [完成]
```

同时说明下一步：把 `.mod` 文件放入 Mods 文件夹，然后正常启动游戏，在主菜单 Mods 页面启用。

失败状态必须分成两层：

- 首屏给玩家一句可行动的中文，例如“检测到游戏仍在运行，请关闭后重试”；
- `技术信息` 展开原异常文本、路径和哈希，提供 `复制信息`，方便反馈问题。

不得把 `Engine changed since installation` 一类内部英文直接作为唯一提示。

## 8. 安全与兼容约束

- 每次实际写入前重新生成快照，不能沿用扫描时的旧检查结果；
- 游戏进程检查必须限定到所选目录，不能因为另一份游戏正在运行而阻止当前副本；
- 不认识的引擎、未知加载器和无效备份一律只读展示，不提供强制覆盖；
- 安装失败后再次读取文件哈希，明确报告“未进行更改”或“已恢复到安装前状态”；
- 符号链接和重解析点仍由核心层拒绝；
- 卸载只恢复加载器负责的文件，保留 `mods/`、`tc-modloader-data/` 和独立存档；
- 无界面参数和退出码保持兼容，避免破坏现有发布测试。

## 9. 分四刀实现

### 第一刀：核心/UI 解耦

- 把 `install(root, remove)` 拆为只读 `inspect` 与明确的 `install`、`uninstall` 操作；
- 引入结构化错误，但暂时保留旧 MessageBox 外观；
- 现有 `tests/setup.ps1` 全部通过，证明没有改变文件语义。

### 第二刀：安装位置中心外壳

- 创建新主窗口和响应式两栏布局；
- 实现 Steam 发现、手动添加、去重和异步状态扫描；
- 完成所有只读状态及不兼容/空状态展示；
- 此阶段按钮可以只接测试桩，不写文件。

### 第三刀：安装与维护交互

- 接入安装、升级、修复、卸载和权限提升；
- 加入内联确认、工作阶段、成功/失败结果与日志入口；
- 操作完成后自动重新扫描当前位置；
- 保持每个状态只有一个主操作。

### 第四刀：发布质量

- 添加图标、版本资源、DPI manifest、键盘操作和高对比度适配；
- 更新安装文档与发布截图；
- 补齐状态矩阵测试、权限失败测试和手工视觉检查；
- 在真实安装、旧版升级、重复修复、卸载和不兼容游戏副本上完成最终验证。

## 10. 测试计划

### 自动化

保留现有安装器测试，并为每种磁盘状态准备临时目录夹具：

- 原版引擎、无备份；
- 当前加载器和有效备份；
- 已知旧加载器和有效备份；
- 未知引擎；
- 备份缺失；
- 备份哈希错误；
- 不兼容游戏 EXE；
- 重复安装和重复卸载；
- 写入失败时目标文件保持原状；
- 两个候选路径的规范化与去重。

状态到主动作的映射应做成纯函数并逐项测试，避免某个错误状态意外出现安装按钮。

### 手工验证

- Windows 10 与 Windows 11；
- 100%、125%、150%、200% 缩放；
- 深色、浅色和高对比度；
- 仅键盘完成位置选择、安装确认和卸载确认；
- 路径包含中文、空格和较长目录名；
- 游戏正在运行、UAC 被取消、目录只读；
- 多个游戏副本中一个兼容、一个不兼容；
- 屏幕阅读器能读出按钮名称、当前选择和错误文本。

## 11. 首发验收标准

满足以下条件后，安装器界面可以随 Mod Loader 发布：

1. 玩家在自动发现成功时，两次点击以内开始安装；
2. 未自动发现时，手动选择后回到主窗口并看到兼容结论，而不是立即写文件；
3. 安装、升级、修复和卸载都复用同一套已测试核心逻辑；
4. 任何不兼容或备份异常状态都不能触发覆盖；
5. 操作结束后无需重开安装器即可看到最终状态；
6. 无界面安装/卸载及现有自动化测试保持兼容；
7. 安装器仍是一个可独立分发的 EXE，不要求玩家安装额外运行库。
