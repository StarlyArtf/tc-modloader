# 原版仿真常量移位优化（2026-10-08）

继已安装的冗余指令删除优化之后，继续优化游戏原版仿真编译器生成的 x64 程序。此次没有修改 TC-Verilog 生成器。测量直接使用仿真周期增量和时间，不调整速度显示。

## 实现与边界

游戏生成的 `MOV ECX,imm32; SHL/SHR/SAR r64,CL` 在满足证明条件时改用立即数移位。保留 ECX 的赋值，仅把三字节移位替换成四字节形式；移位数保留低八位，64 位硬件移位继续使用相同的计数掩码。沿用上一版冗余复制和零移位删除，并重新定位入口及直接相对跳转/调用。

仅接受无前缀的五字节 `B9 imm32` 和完整 64 位寄存器移位；不改栈指针。禁止优化直接分支、调用或入口可跳入的移位。变量与立即数形式可能产生不同的未定义 OF/AF，因此进一步要求随后有限的直线代码中，所有算术标志位都被 ADD/SUB/CMP 覆盖，并且覆盖前没有标志位观察者或未知指令。CALL、RET、条件跳转、PUSHF、SETcc、ADC 等均终止证明。短跳转扩张后越界时整块回退原码。

独立复核发现并修正两项 HDE 解码边界：解码器没有填充 `h.rex`，不能用它判断无 REX 前缀；部分 `0x67` 寻址被错误解码。ECX 常量现在严格核对原始首字节 B9 和 IMM32，零移位删除也使用此条件；遇到任何地址宽度前缀，整块回退。两个问题均先用失败测试复现，再修复通过。

冻结的原版 Overture CPU（111 个实际元件、展开后 125 个节点）实际编译日志显示：移除 1,383 条冗余指令，替换 656 处常量移位，程序 83,459 → 79,966 字节，入口 8,495 → 7,886。上一版为 79,310 字节、入口 7,862。代码更短本身不能代表更快，实际测速见下文。

## 当前安装版与候选版对照

相同冻结电路、相同 Mod 包，旧/新/新/旧交替运行，双方都启用各自的 JIT 优化。每组独立游戏与克隆存档，关闭波形录制，期间不运行编译或其他 CPU 密集测试。采用运行约 20–37 秒内的精确时间和周期差计算 MHz，并拒绝周期重置。原始结果保存完整加载器哈希与日志目录。
