# 通用仿真热路径优化（2026-10-07）

第一轮优化已完成。改动位于加载器生成的游戏 JIT 源码，原版元件和 TC-Verilog 元件共同使用这条仿真路径。

## 改动与原因

1. 未采集波形时跳过 `tc_scope_tick` DLL 调用。此前每个周期都先进入 DLL，再检查是否正在录制；现在 JIT 直接读取稳定地址上的采集开关，仅在录制时调用。开始、停止和逐周期采集的语义保留。
2. 9–64 位在线可编辑常量直接读取永久原子槽。此前 CYCLE/REFRESH 阶段都需要 DLL 调用、TLS 缓存和组件 ID 查表；现在编译时确定地址，执行时读取槽值。原有 setter、旧读取桥和无需重编译的在线修改继续可用。

直接读取针对已固定的 Windows x64 ABI；编译期检查原子大小及无锁支持。常量槽单独分配并保持地址稳定，不随注册表扩容移动。

## 性能证据

对比使用同一台电脑、游戏 2.1.334、相同 Mod 包与冻结电路。优化前加载器由本次改动之前的工作区源码构建，优化后只包含上述产品改动。游戏与存档均在独立临时目录运行，未修改真实存档。测试顺序执行，波形录制关闭。

| 实际执行的电路 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 玩家冻结电路，83 个顶层元件，包含原版元件、RAM 和 TC-Verilog RV32I | 4.253 MHz | 5.114 MHz | +20.2% |
| 空沙盒，生成程序确认元件数为 0，显式请求全速 | 104.854 MHz | 191.744 MHz | +82.9% |

指标为模拟周期增量除以测试日志时间增量，包含前台渲染与测试驱动的运行请求开销。玩家电路取日志 t=20 到 t=34，空沙盒取 t=20 到 t=33。日志时间只有整数秒，且这里只报告单组对比，数值应视作近似值。它与游戏界面瞬时显示的 380/16 MHz 口径不同，不能直接推算玩家界面的新频率，也不能把空电路增幅套到复杂电路。
