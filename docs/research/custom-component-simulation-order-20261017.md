# 自定义元件封装、开关与仿真代码对照（2026-10-17）

用户观察：同样的电路封装成普通自定义元件后更快，尤其是带 Switch 的电路。
本轮调查生成源码、最终机器码和真实仿真周期增量；没有修改产品代码或玩家安装。
用户尚未指定观察到该现象的两份存档，本轮使用独立构造的受控电路，不将结论推广到其具体存档。

后续新增元件的对照见 [MUX、译码器、寄存器与 Splitter/Maker 调查](custom-component-other-kinds-20261017.md)。
新增寄存器样例出现了求值顺序变化，因此本文“顺序相同”的结论仅针对下述首批样例。

## 结论

- 普通自定义元件仍展开成内部元件参与编译，没有变成真值表，也没有跳过内部 Switch。
- 本轮各对照中，忽略封装和输入缓冲节点后，主要元件的求值顺序相同。
  先前把“封装改变遍历顺序”作为提速解释，证据不足，不能作为已确定原因。
- Switch 样例中，封装引入 `com_cc_input_buffer`。控制输入在这里先成为 U1 临时值，
  后续使用这个临时值；直接放置版在各使用点转换控制输入。最终机器码存在明确差异：
  封装版循环少了 16 条 `and ...,0x1`，涉及栈的指令少 32 条。
- 这支持“封装边界改变临时值和位宽处理，影响编译器生成代码的质量”的解释。
  尚未用单变量源码改写实验，将速度差异完全归因于其中某一条规则；没有硬件性能采样。
- 高阻态合并和冲突检查均保留，因此没有证据支持“封装自动省掉总线检查”。

## 普通组合逻辑对照

四条独立支路，每条 32 个 8 位 NOT/Increment/Negate，Counter 驱动，Delay Line 接收。
三种保存：直接放置并分组、直接放置但交错组件数组、封装为四个普通自定义元件。

- 两种直接放置版：去掉注释/空白后，每周期循环完全一致。
- 封装版：增加四个 U8 输入别名；消除这四个别名并归一化变量/状态槽名称后，循环也相同。
- 归一化 SHA-256：`edacb7f6c607c18483cf6180d25350e72bc23ceea6a6cb78c3a646121e298445`。
- 开启优化，按封装/直接/直接/封装顺序测试：
  12.6243 / 13.1959 / 12.0903 / 12.6504 MHz，两组平均都约 12.64 MHz。
- 该普通样例的定义头延迟是人工测试值，两版显示延迟评分不同；不用于证明评分等价。
  每周期循环已单独对照，限速按相同 command speed 配置，未使用关卡判定。

## Switch 共享总线对照

16 组独立支路，每组两个 8 位 Counter 数据源、一个交替选择信号、一个 NOT、
两个 Switch、共用输出总线和一个 Delay Line。选择信号及其反相信号分别控制两个开关。
直接版和封装版都由游戏实际编译并运行。封装版只是普通电路定义，没有原生逻辑回调。

两版门数评分均为 **7296**，延迟评分均为 **22**。
Counter 的控制信号在游戏推导后为 U2，封装的 Select 输入脚明确声明为 1 位；
两版开关/NOT 都按最低位使用它。这正是本例可观察到的位宽转换差别，
不能推广成“任何已经是 1 位的控制信号也一定有相同收益”。

每种模式按直接/封装/封装/直接运行，取 t=20～37 秒内的首尾周期差除以时间差，
每次保留 16～17 个样本，不采用界面 MHz 读数。

| 机器码优化 | 直接两次 MHz | 封装两次 MHz | 直接均值 | 封装均值 | 均值差 |
|---|---|---|---:|---:|---:|
| 关闭 | 6.0213、5.6970 | 6.4476、6.3706 | 5.8592 | 6.4091 | +9.39% |
| 开启 | 13.3172、14.2537 | 13.7664、14.4594 | 13.7855 | 14.1129 | +2.38% |

只有每版两次测量。开启优化后的组内波动大于均值差，不能承诺稳定 +2.38%。
开启优化的四次运行均在暂停的 cycle=39，通过仿真读取 API 检查 16 个 Delay Line 的状态值：
全部匹配预期 Counter 值。该检查用于排除输出未连接造成的空跑，不是完整的选择器真值表验证。

### 每周期源码

| 静态项目 | 直接 | 封装 |
|---|---:|---:|
| Switch | 32 | 32 |
| NOT | 16 | 16 |
| 冲突检查 `halt()` 位置 | 16 | 16 |
| OR / AND 驱动合并赋值 | 32 / 32 | 32 / 32 |
| `load()` / `store()` | 112 / 176 | 112 / 176 |
| 新增输入缓冲 | 0 | 48 |

以上是源码静态计数，包含常量条件内的语句，不等于实际执行次数。

### 开启优化后的代表性机器码

定位方式：从生成源码读取仿真状态基址及循环第一个状态读取的偏移；
在最终二进制中寻找以该地址开头、由条件回跳返回的每周期循环。
使用 GNU objdump `--insn-width=16` 避免把续行字节误计为指令。

| 静态项目 | 直接 | 封装 |
|---|---:|---:|
| 每周期循环指令 | 1670 | 1637 |
| 含 `[rsp...]` 操作数的指令 | 212 | 180 |
| `and ...,0x1` | 32 | 16 |
| 从栈 `movzx` | 65 | 49 |
| 向栈 `mov` | 106 | 90 |
| 条件跳转 | 50 | 50 |
| 完整生成程序字节数 | 40482 | 44798 |

完整程序包含刷新等路径，封装版反而更大，不能以整个文件大小推断热循环速度。
循环内存在条件分支，上表同样是静态计数。
