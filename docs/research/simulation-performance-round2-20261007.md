## 原版电路对比

优先测量真实存档 Overture 的纯原版 CPU，约 111 个实际元件，展开后 125 个节点；电路冻结为 `build/sim-round2-overture.data`。每个运行使用独立游戏和存档副本，同一安装中的 Verilog Mod 包保持不变。请求全速后仅提交一次长期运行命令，避免逐帧重新提交导致批次从头增长。

指标为日志 t=20 到 t=37 的周期增量除以经过时间。包含渲染和测试驱动，不能直接换算游戏界面 MHz；每个候选只有一组有效测量，结果用于否决缺乏收益的候选，不用于宣称精确的回退百分比。

## 执行热点证据

对原版 CPU 的第一轮加载器使用 WPR CPU 采样，并由测试探针在游戏执行之前保存完整 JIT 字节。探针仅用于隔离测试，通过显式 `-JitDump` 启用，不修改指令或参数。游戏版本和 JIT ABI 固定为 2.1.334。该采样运行不纳入上述 A/B 速度表。

- 原始隔离目录：`build/repro-cfc501e1d7e0498a8de1c52e6d641688`。
- JIT 字节：该目录下 `game/tc-modloader-data/plugin-data/dev.pin-shape-probe/jit-code-1.bin`，83,459 字节，入口偏移 8,495，执行线程 35,900。
- ETL：`build/sim-round2-stock-cpu.etl`。仿真线程 25–37 秒共 11,959 个采样，其中 11,675 个落在该 JIT，11,674 个落在逐周期内层循环（约 97.6%）。
- 根据对齐的地址推定 JIT 基址为 `0x29c49cc0000`；全部 11,675 个 JIT 采样地址均匹配保存机器码的指令边界。这是通过采样地址与机器码匹配推定的基址，探针未直接记录运行时分配地址。
- 内层循环为机器码偏移 `0x963b` 到 `0xcc86`，回跳已在反汇编中确认。循环体静态包含 3,143 条指令，其中 564 条显式引用栈地址，334 条为移位。分支意味着每周期并非执行全部静态指令。
- 分析文件：`build/sim-round2-stock-jit.asm`、`build/sim-round2-stock-simthread-samples.csv` 和 `build/sim-round2-stock-jit-stats.json`。

采样地址可能受到处理器采样偏移影响，不能把某条栈读写或转换指令的采样数直接视为它造成的停顿。此证据确认时间主要用于原版元件循环，而未证明寄存器溢出或类型转换分别占用多少时间。

现有 xperf 8.1 可以生成按模块统计，但其事件导出在当前 Windows 的另一提供程序上报错 `0x80070570`。新增 `tests/etw-sim-samples.cpp` 直接通过 Windows ProcessTrace 读取经典 x64 SampledProfile，按指定线程和本轮稳态窗口过滤，成功得到上述采样。它是开发诊断工具，未进入游戏发布包。

## 后续方向与验证要求

下一步应针对原版元件的 JIT 代码生成，检查重复位宽转换、总线临时值的存活范围和寄存器分配。大范围把 var 改为 let 的方案已有反例，不能作为通用优化。改变转换或求值位置前，需要证明反馈电路、同周期多驱动总线、在线输入和内存读取语义保持一致，并逐周期对比真实原版 CPU 的状态。

本轮保留的工具改动：`repro-user-board.ps1` 增加 `-BenchmarkOnce` 与 `-JitDump` 并恢复相关环境变量；状态与波形 playtest 增加 `-Loader`，方便直接测试候选而无需覆盖 dist。热路径与波形单元测试重新执行通过，相关文件的 diff 空白检查通过。仓库整体 diff 检查仍存在无关的 `docs/PLAN-float-components.md:3` 尾随空格；没有修改该已有文件。

诊断工具经独立代码审阅。审阅指出异常退出时测试进程可能留在后台，已将进程关闭移到 finally，同时用内层 finally 保证环境恢复。最后的版本检查和 JIT 捕获实测位于 `build/repro-fce598d26e2a40dd8cc2a5677fc8a7a8`；成功捕获同长度机器码，探针加载成功，隔离测试进程已退出。Windows 采样记录也已停止。
